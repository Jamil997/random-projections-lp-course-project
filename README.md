# Random Projections for Linear Programming

Algorithms for Big Data course project by Jamil Zhumabek, MBZUAI.

This project studies the projected relaxation

```math
\min c^T x\quad\text{subject to}\quad SAx=Sb,\quad x\geq0
```

of an original linear program with equality constraints `Ax=b`. It combines a
focused theoretical report with a newly run, reproducible empirical evaluation.
Reducing the number of constraints can shorten a solver call, but the resulting
vector must still satisfy the original equalities and nonnegativity.

## New: established Netlib benchmarks

The 4 October 2026 extension adds ADLITTLE, AFIRO, BLEND, SCFXM1, and STOCFOR1.
These include an oil-refinery model variant and a forestry-planning model;
they are historical benchmarks, not newly collected field data.
Each LP is converted exactly to nonnegative equality standard form, and its
native and converted optimum are checked against the published reference.

Three projectors (Gaussian, sparse-valued, CountSketch), two row ratios
(`0.5`, `0.75`), and ten seeds give **300 projections of five fixed LPs**.
Unlike the dense synthetic suite, originals and non-Gaussian sketches use CSR.

| Netlib finding | Recorded result |
|---|---|
| Projected statuses | 84 finite optima; 216 unbounded; no errors/limits |
| Unboundedness diagnostics | All 216 have saved, verified numerical recession rays |
| Raw projected original-feasibility | 0/84 accepted; none satisfies the native rows either |
| Dual recovery | 84/84 selected bases singular; no candidate returned |
| Primal recovery | 84 rank-deficient solves; 0/84 candidates accepted |
| Full-dimensional orthogonal controls | 5/5 original-feasible and objective-matching |

CountSketch retains much smaller projected matrix buffers than dense Gaussian
projection in these tests, but **this is not a successful speedup of original-LP
solution**. Storage counts exclude solver internals and the dense copy used by
the legacy recovery heuristics. The results concern the basic relaxation and
two heuristics, not all sketch-based optimization or retrieval methods.

Saved vectors, per-run times/statuses/storage, summaries and checksums are in
[`results/netlib`](results/netlib). The full-dimensional controls are separate
from the 300 compressed runs. No artificial variable bounds are added to
suppress unboundedness. The five examples are a focused course-project suite,
not a large-scale hardware-limit or industrial-representativeness study.

## Reproduce the experiments

Use Python 3.12 from the repository root:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python experiments/rerun.py --output-dir results/rerun-local
.venv/bin/python experiments/diagnose_statuses.py --output-dir results/rerun-local
.venv/bin/python experiments/verify_results.py --output-dir results/rerun-local
.venv/bin/python experiments/fetch_netlib.py
.venv/bin/python experiments/netlib_benchmark.py --output-dir results/rerun-netlib-local
.venv/bin/python experiments/verify_netlib.py --output-dir results/rerun-netlib-local
```

Use a new output directory for each run. The supplied baseline records are
retained under `results/baseline/`; the experiment runner refuses to overwrite
a nonempty results directory. Timings vary with hardware and load. The default
configuration is intentionally small, with ten independently seeded instances
per synthetic configuration and ten projector seeds per fixed Netlib LP.
The downloader uses a pinned COIN-OR mirror and verifies the committed hashes.
Raw MPS files are not redistributed; see [data/netlib/README.md](data/netlib/README.md).
The MPS reader is a private interface bundled with the pinned SciPy version;
changing SciPy may require adapting the reader.

## Experimental design

| Component | Updated experiment |
|---|---|
| Original LP | `min 1^T x`, `Ax=b`, `x>=0` |
| Matrix sizes `(m,n)` | `(100,150)`, `(250,375)`, `(500,750)` |
| Target nonzero density | `0.1`, `0.5` |
| Projected dimension | `k=floor(m/2)` |
| Feasible family | `x0~U[0,1]^n`, `b=A x0`; Gaussian projection |
| Legacy infeasible family | `A>=0`, every entry of `b` negative |
| Additional stress family | `A>=0`, only `b[0]` negative, other entries positive |
| Infeasible projectors | Sparse-valued and orthogonal, paired on each original LP |
| Recovery | Lifted-dual basis solve; primal-support SVD solve |
| Solver | Explicit HiGHS dual simplex for both original and projected LPs |

The default suite has 180 independent original LPs and 300 projected LPs.
The additional stress family tests sensitivity to the infeasibility generator;
it is not presented as an exact rerun of the older notebook's generator.
Both infeasible families are easy for presolve before projection. All input
matrices are stored densely, so this is not a sparse-storage benchmark.

## Reading the results

The committed baseline was executed on 13 September 2026 with seed `20260913`:

| Family | Projected outcomes | Interpretation |
|---|---|---|
| Feasible | 60 optimal | Neither recovery method produced an accepted original-feasible vector: 0/60 each |
| Legacy all-negative | 120 infeasible | Infeasibility was retained in every sampled projection |
| Additional mixed-sign | 99 infeasible, 17 optimal, 4 errors | Some infeasible originals have feasible projected relaxations |

Separate interior-point diagnostics classified the four errors as infeasible;
the primary counts above are unchanged. These findings apply to this small,
specified benchmark, not to arbitrary LPs or all recovery algorithms.

`results/baseline/raw.csv` records each projected run, its original counterpart,
seeds, solver statuses, timing components, and quality metrics. `summary.json`
and `summary.csv` contain means, sample standard deviations, and observation
counts. `environment.json` records the software environment and script hash.

A recovered vector is accepted only when it satisfies both the original
equalities and nonnegativity at the stated tolerance. A small equality residual
alone is not a valid LP solution. Objective discrepancies for infeasible
recovered vectors are diagnostics, not approximation guarantees.

Projected solver statuses are reported explicitly. A feasible projected LP can
come from an infeasible original LP; unknown or error statuses are kept separate.
`status_diagnostics.json` records additional solver checks without replacing the
primary observations or adding diagnostic time to benchmark times.

`deterministic_checks.json` covers the unboundedness examples, a full-dimensional
projection check, and the equality-dual sign convention. Synthetic random benchmarks use
positive objective coefficients and therefore do not test unboundedness;
the new Netlib suite does.

## Report

The report is in `report/main.tex`, with a compiled `report/main.pdf`. Its style
follows the original thesis. The LaTeX file is self-contained, with embedded
